# passwordSafe

Локальный менеджер паролей для Windows с зашифрованным хранилищем.

## Требования для сборки

- Windows 10 или 11;
- Python 3.14 с командой `py` или `python` в `PATH`;
- доступ к интернету при первом запуске скрипта.

## Сборка

Откройте PowerShell в корне проекта и выполните:

```powershell
.\build.ps1
```

Скрипт сам создаст `.venv`, установит зависимости из `requirements-build.lock` и соберёт приложение с установщиком. GitHub Actions использует тот же lock-файл.

Если выполнение PowerShell-скриптов запрещено политикой системы:

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

Готовые файлы:

```text
dist\passwordSafe-Setup.exe
dist\passwordSafe\passwordSafe.exe
```

Для установки запустите `passwordSafe-Setup.exe` и выберите папку, где будет находиться приложение.

## Обновление

Откройте **Настройки → Проверить обновления**. passwordSafe сравнит свою версию с последним стабильным релизом и, если есть более новая версия с установщиком, предложит открыть её страницу на GitHub. Если проверка недоступна (например, репозиторий закрыт), можно перейти к списку релизов и войти в GitHub в браузере. Приложение не запрашивает токен GitHub и не запускает установщик автоматически.

На странице релиза скачайте `passwordSafe-Setup.exe`, закройте все окна passwordSafe и запустите установщик. Выберите ту же папку, куда была установлена предыдущая версия. Хранилище и резервные копии находятся отдельно от файлов приложения. Если не знаете папку установки, найдите `passwordSafe.exe` через свойства ярлыка.

Для публикации обновления задайте новую версию `MAJOR.MINOR.PATCH` в `password_safe/version.py`, соберите её через `build.ps1` и приложите `dist\passwordSafe-Setup.exe` к стабильному GitHub Release с тегом `vMAJOR.MINOR.PATCH`. Тега без опубликованного релиза и установщика недостаточно. Для проверки версии в приложении релиз должен быть доступен через API без авторизации; иначе остаётся ручное обновление через браузер.

## Хранилище и резервные копии

- При обычном сохранении `vault.pm2.bak` содержит предыдущую версию основного файла. Если другой экземпляр успел сохранить данные, устаревший сеанс получит ошибку: заблокируйте и разблокируйте его, затем повторите изменение.
- Восстановление доступно на стартовом экране, даже если `vault.pm2` отсутствует. Если рабочий файл был, перед заменой сохраняется `vault.pm2.pre-restore.bak`. Для открытия копии нужен мастер-пароль, действовавший при её создании.
- После смены мастер-пароля приложение обновляет автоматическую копию отдельно. Если обновление не удалось, новый пароль уже действует для рабочего файла. Экспортированные копии не меняются: сохраните новую копию с новым паролем. Старые хранилища открываются без обязательной смены пароля; новые и заново зашифрованные при смене пароля используют усиленный профиль scrypt.
- Для миграции с открытого `records.json` выберите фактический файл на стартовом экране. Приложение проверит всю исходную коллекцию и отдельно откроет зашифрованную копию перед удалением исходника. При частичном сбое используйте «Завершить миграцию» в настройках **до изменения записей**. Миграция не является гарантией физического стирания открытого файла с диска или из других копий.

## Архитектура

`models.py` и `password_safe/domain.py` содержат модель и правила. Сценарии в `password_safe/application.py` зависят от контрактов `password_safe/ports.py`, а не от Tk или файлового формата. GUI в `password_manager_ui.py` и `record_window.py` вызывает сценарии; файловые, браузерные и системные адаптеры подключаются в `password_manager_app.py`.

## Параметры скрипта

```powershell
.\build.ps1 -SkipDependencies  # не устанавливать зависимости, только сверить их с lock-файлом
.\build.ps1 -DependenciesOnly  # подготовить окружение, не собирать EXE
.\build.ps1 -SkipInstaller     # собрать только приложение
.\build.ps1 -CleanOnly         # удалить каталоги build и dist
```
